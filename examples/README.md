# embkit examples

Runnable, end-to-end walkthroughs of the core embkit workflows a computational-biology
researcher reaches for when building and testing embedding models. Each script runs
**out of the box on the small bundled data in [`data/`](data/)** — no network access, no
GPU, no multi-GB downloads — and prints the quality metrics you'd want to see before
trusting the model. The real-data variant (GTEx, larger ESM2 models) is shown in each
script's docstring.

```
examples/
├── README.md
├── train_vae.py            # 1. Build + test a VAE on gene expression
├── protein_embed.py        # 2. Generate protein embeddings from FASTA via ESM2
├── analyze_embeddings.py   # 3. Project, cluster, and score any embedding matrix
└── data/                   # small inputs (committed) + generated outputs
    ├── expression.tsv         # 24 samples x 30 genes (rows=samples, cols=genes)
    ├── labels.tsv             # sample -> condition label (for scoring)
    ├── sequences.fasta        # 10 short protein/peptide sequences
    ├── protein_labels.tsv     # sequence -> homolog group
    # generated by running the scripts:
    ├── vae.model              # trained VAE (from train_vae.py)
    ├── vae_embedding.tsv      # latent embedding (from train_vae.py)
    ├── protein_embeddings.tsv # ESM2 embeddings (from protein_embed.py)
    ├── *_pca_2d.png / *_umap_2d.png   # 2D plots (from analyze_embeddings.py)
```

## Prerequisites

A Python environment with `embkit` and its dependencies installed. See the top-level
[README](../README.md) for install steps. The scripts additionally use `pandas`,
`numpy`, `scikit-learn`, `umap-learn`, and `matplotlib` (all standard in a bio
environment). The protein example needs `fair-esm` for the CLI path; if it's missing the
script falls back to the bundled pre-computed embeddings.

## 1. Train a VAE and test it — `train_vae.py`

The build-and-test loop in one script: load → normalize → train → save/load → encode →
score reconstruction.

```bash
python examples/train_vae.py
```

What to look for in the output:
- **Per-gene Pearson r** — the model should reconstruct the high-signal genes well
  (r ≈ 0.9+) and leave the low-signal genes near r ≈ 0. That contrast is the whole point.
- **Global MAE / mean r** — a single number summarising overall reconstruction fidelity.

To run on real GTEx data instead of the bundled 30-gene matrix, see the
"Real-data variant" section of the script's docstring (uses `embkit.resources.GTEx` +
`Hugo` + `embkit.files.loaders.load_gct`).

## 2. Protein embeddings from FASTA — `protein_embed.py`

Generates fixed-length sequence embeddings with Meta's ESM2 via the `embkit protein
encode` CLI, then loads and summarises them.

```bash
# default (t33, ~3 GB memory; fine on GPU, slow but works on CPU)
python examples/protein_embed.py

# fastest option, best for a quick CPU demo
python examples/protein_embed.py --model t6 --batch-size 16

# no GPU / no fair-esm / no network — use the bundled pre-computed embeddings
python examples/protein_embed.py --fallback
```

What to look for:
- **Within-group vs between-group cosine** — homologous sequences (same label) should be
  closer than unrelated ones. A positive separation margin means ESM2 captured the family.

## 3. Project, cluster, score — `analyze_embeddings.py`

Works on any embedding TSV (rows = samples, columns = dims) plus a matching labels file.
By default it analyzes the VAE embedding from step 1.

```bash
# VAE embedding (default)
python examples/analyze_embeddings.py

# protein embedding
python examples/analyze_embeddings.py \
    --embedding examples/data/protein_embeddings.tsv \
    --labels examples/data/protein_labels.tsv
```

Outputs:
- **ARI (Adjusted Rand Index)** — 0 = random, 1 = perfect. Tells you whether the learned
  embedding actually recovered the known group structure.
- **Silhouette score** — −1..1, higher = tighter, better-separated clusters.
- **PCA / UMAP 2D plots** — saved as PNGs under `data/` for visual inspection.

## The three-step pipeline

```
expression.tsv ──► train_vae.py ──► vae_embedding.tsv ──┐
                                                          ├──► analyze_embeddings.py ──► ARI / silhouette / plots
protein/sequences.fasta ──► protein_embed.py ──► protein_embeddings.tsv ─┘
```

The protein and VAE branches are independent; both feed the same analysis script.

## Design notes

- **No `model.fit()`** — embkit models don't have a `fit` method. Training always goes
  through `embkit.optimize.fit_vae(model, X, ...)`. This is the #1 thing that breaks
  naive copy-pasted code.
- **`BaseVAE` vs `VAE`** — `VAE` only pairs a pre-built encoder+decoder; `BaseVAE` is the
  concrete class that builds them from layer specs. The examples use `BaseVAE`.
- **Loss ↔ output head must match** — a linear output head pairs with `MSEVAELoss` (recon
  is directly comparable to the [0,1] input); a sigmoid head pairs with `BCE*Loss`.
- **`scanpy` is not required** — the analysis uses plain `sklearn` + `umap-learn`.
- The generated artifacts (`.model`, `*_embedding.tsv`, `*.png`) live under `data/` and
  are safe to delete and regenerate by re-running the scripts.
